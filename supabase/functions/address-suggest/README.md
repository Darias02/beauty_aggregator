# Подсказки городов и адресов

Endpoint использует только `suggest/address` DaData. SDK, API стандартизации, геокодирование и
другие дополнительные сервисы не подключаются. Изменений схемы БД нет.

## Контракт

`POST /functions/v1/address-suggest`, `Content-Type: application/json`:

```json
{ "init_data": "signed Telegram initData", "mode": "city", "query": "Мос" }
```

Для адреса передайте `mode: "address"`. Необязательный `city` ограничивает поиск введённым городом.
Если город выбран из подсказки, клиент дополнительно передаёт `city_id`, UUID ФИАС. В профиле поиск
идёт по России без ограничения городом.

Ответ содержит до пяти объектов `{label, value, cityId}` в `suggestions`. У города `value` содержит
название без префикса `г`, у адреса полную строку. Клиент показывает `label` через `textContent`.
Регион остаётся видимым в списке. ФИАС ID используется только как временный контекст следующего
запроса. Имена одноимённых городов в БД по-прежнему не различаются по региону: это ограничение
существующего текстового поиска, а не новая модель географии.

Пустой город не проходит существующий `slots-write` и SQL RPC. Проверка добавлена также в форму.
Адрес необязателен. Ручной ввод работает независимо от подсказок. Город и адрес слота сохраняются
прежним API. Адрес профиля сохраняется отдельно, при выборе подсказки или уходе из поля. Записи
профиля выполняются последовательно. Существующие слоты не обновляются при редактировании профиля.

Ошибки: `400 INVALID_REQUEST`, `401 UNAUTHORIZED`, `405 METHOD_NOT_ALLOWED`, `429 RATE_LIMITED`,
`503 SUGGESTIONS_UNAVAILABLE`. На 429 возвращается `Retry-After: 60`. Ошибки и ответы провайдера не
возвращаются пользователю целиком.

## Защита и ограничения

Подпись и срок действия Telegram `init_data` проверяются общим валидатором BB. Клиентский ID, origin
и publishable key не заменяют проверку подписи. Тело ограничено 16 KiB, поисковая строка 200
символами, ответ провайдера 128 KiB. URL провайдера фиксирован, редиректы запрещены, таймаут
обращения 3 секунды. Telegram-данные провайдеру не передаются. Код не логирует ключи или адресные
запросы.

Локальные счётчики ограничивают пользователя 30 запросами в минуту и экземпляр 200 запросами в
минуту. Они ограничены по памяти и сбрасываются каждую минуту. **Они не являются глобальным
распределённым ограничителем.** Разные экземпляры Edge Functions имеют независимые счётчики;
повторное использование подписанного `init_data` в пределах его TTL допустимо существующим
валидатором BB.

Общий суточный предел обеспечивает только бесплатная подписка DaData: 10 000 запросов на аккаунт,
суммарно с другими использующими эту подписку API. После исчерпания лимита подсказки недоступны,
ручное сохранение остаётся доступным. Без общей изменяемой памяти нельзя гарантировать глобальный
лимит на пользователя. Несколько авторизованных клиентов могут исчерпать общую квоту. Строгий общий
лимит потребует отдельно согласованного общего хранилища или ограничения на API gateway. В этой
версии дополнительные сервисы и таблицы не создаются.

`DADATA_FREE_TIER_ENABLED=true` означает явное подтверждение настройки бесплатного аккаунта, но не
проверяет его тариф через биллинговый API. Не используйте токен аккаунта с платной подпиской. Код не
покупает услуги и не переключает тариф.

## Локальная проверка без ключа

Из корня репозитория:

```sh
deno task --cwd supabase/functions/address-suggest check
deno task --cwd supabase/functions/address-suggest lint
deno task --cwd supabase/functions/address-suggest test
deno task --cwd supabase/functions/master-profile test
deno task --cwd supabase/functions/slots-write test
python3 -m pytest tests/address_suggestions -q -p no:cacheprovider
python3 -m pytest tests/address_suggestions --address-artifact -q -p no:cacheprovider
```

Серверные тесты проверяют настоящие подписи тестового Telegram-токена и обработчик, а HTTP DaData
заменяют фиксированным ответом. Браузерные тесты используют локальный сервер BB-75, установленный
Chrome и перехватывают все API. Внешняя сеть блокируется. Они проверяют выбор, ручной ввод,
обязательность города, сохранение, повторное открытие, независимость профиля и слота, вывод клиенту,
403/429/503/network, пустой результат, отмену устаревших ответов и мобильные размеры. Проверяются также
последовательные записи при медленном первом сохранении и защита набираемого
адреса от запоздавшей загрузки профиля. Это не
проверка реального аккаунта DaData, production БД или физического Telegram WebView.

## Подключение настоящего бесплатного ключа

1. Зарегистрируйтесь на https://dadata.ru и подтвердите почту.
2. В личном кабинете проверьте, что выбран бесплатный тариф без платных услуг.
3. Скопируйте API-ключ. Secret key для этого endpoint не нужен.
4. В локальном серверном окружении задайте `DADATA_API_KEY` и `DADATA_FREE_TIER_ENABLED=true`.
   `BOT_TOKEN` нужен общему валидатору Telegram. Для тестового окружения используйте отдельного
   тестового бота.
5. Храните локальный env-файл за пределами репозитория, например
   `~/.config/beauty-booking/address-suggest.local.env`, с правами `600`. Передайте его локальному
   рантайму Edge Functions как серверный env-file. Не добавляйте ключ в `webapp/js/config.js`, HTML,
   URL, Git или чат.

Для будущего согласованного развёртывания эти переменные задаются в серверных Supabase Edge Function
Secrets целевого окружения. Эта задача не задаёт remote secrets, не применяет миграции, не публикует
функцию и не меняет production.

На реальных iOS/Android отдельно проверьте тап по варианту, прокрутку списка с открытой клавиатурой,
закрытие списка и повторное открытие профиля. Браузерный resize моделирует доступную высоту, но не
заменяет нативную клавиатуру Telegram.

Источники: https://dadata.ru/api/suggest/address/ и https://dadata.ru/pricing/.

## Локальный preview с настоящей DaData

После заполнения приватного env-файла запустите из корня репозитория:

```sh
python3 tools/local_address_preview.py
```

Откройте http://127.0.0.1:8076, переключитесь в роль мастера и откройте профиль
или создание слота. На порту 8077 работает настоящий обработчик подсказок в Deno.
Его сетевые разрешения допускают только loopback и `suggestions.dadata.ru:443`.
Браузер получает подменённую конфигурацию API, CSP и fetch guard, которые запрещают
внешние обращения. Сервер не читает production env-файлы и не обращается к Supabase.

Preview требует сгенерированный синтетический `BOT_TOKEN` с префиксом `000000000:`
в приватном файле. Это локальный ключ для подписи тестового init_data, а не токен
реального бота. Не заменяйте его production-токеном. Deno читает только указанный
файл настроек, без доступа к переменным окружения оболочки.

Профиль, слоты и записи хранятся в памяти MockAPI. Обновление страницы сохраняет
их, перезапуск процесса сбрасывает. Это проверка UI и реального получения подсказок,
а не проверка записи в PostgreSQL. Остановите preview через Ctrl+C в его терминале.

Для повторяемой проверки в другом терминале:

```sh
python3 tools/check_local_address_preview.py
```

Проверка делает несколько настоящих запросов только к `suggest/address` через
локальный обработчик. Она выводит только результаты проверок и HTTP-статусы.
Ключи, заголовки и browser traces не печатаются. Снимок тестового профиля сохраняется
в `~/.config/beauty-booking/local-address-check.png` с правами `600`.
