# Локальная подготовка develop

Исходная версия приватной разработки: `fa8f9fd677f6b9865c371aaddbd8be39ef08d9cd`.
Основная `main` и свежеполученная `origin/main` совпадали с
`b0db59f875324c91b1a837cdb8b21441d1eef3c2`. Новая `develop` создана от этой `main`
в отдельном worktree. Исходная история не переносилась через merge и не переписывалась.
Новые коммиты отражают перенос текущих файлов, а не авторство исходной разработки.

Перенесены профили пользователей и мастеров, аватары, каталог, слоты,
бронирования, решения мастера, отмены, сохранение истории, Telegram-проверки,
webhook, уведомления, frontend, 12 SQL migrations, dependency locks и тесты.
Сохранён необходимый vendored WASM с лицензиями. Добавлены локальный preview,
сборщики frontend и общие инструменты проверки и локального восстановления.

В `transfer-manifest.json` указаны SHA-256 для 223 исходных файлов и фикстуры,
97 исключённых путей и перечень адаптаций. Изменения в исходниках приложения,
миграциях и locks отсутствуют относительно исходной версии. Адаптированы только
ignore, документация, путь структурной фикстуры и изоляция браузерных тестов.

Проверка переноса:

```sh
python3 scripts/verify_transfer.py
# Дополнительно при наличии исходного checkout:
python3 scripts/verify_transfer.py --source /path/to/beauty_aggregator_dev
```

## Исключения

Не перенесены audit-каталоги BB-73/BB-77, контрольные точки, инвентаризации,
журналы и отчёты восстановления BB-77. Связанные `tools/release/bb77*`,
`check_recovery_plan.py` и `tests/bb77/` обслуживают приватную процедуру
восстановления и зависят от исключённых свидетельств; приложение их не импортирует.
Общие инструменты release-проверок и тесты BB-73–BB-76 сохранены.

Сборщик SQL использовал приватный каталог BB-73. Вместо него включена
`tests/bb73/schema_fixture.json`, содержащая только необходимые определения
колонок, ограничений и индексов. Пользовательских строк и метаданных сервера нет.
Полные свидетельства аудита исключены. Пакет SQL остаётся материалом для
проверки, а не разрешением применять его к существующей базе.

Исключён старый корневой PNG-снимок экрана как справочный материал без зависимостей.
Его исходная копия и существующая Git-история сохранены. Локальные `.env`,
`supabase/.temp/`, кэши, virtualenv, dist и результаты браузерных тестов не переносились.
Резервные копии не читались и не удалялись.

## Проверки и ограничения

- Локальная Mini App в Chrome: 37 passed, 1 skipped, пропущен production gate.
- Собранный frontend в Chrome: 36 passed, 2 skipped, пропущены только локальные HTTP-сценарии.
- Edge: check, lint, frozen cached-only tests прошли; locks не изменились.
  388 успешных запусков Deno-тестов, включая повторяемые общие наборы, и 13 Node-тестов.
- SQL: 157 passed, локальная одноразовая PostgreSQL, только Unix-сокеты.
- Сборщики и общие release-инструменты: 34 passed и 37 subtests passed.
- Python-регистрация и серверная граница BB-24: 19 passed.
- Отдельные Node-проверки записей мастера и release gate: 13 passed.
- Python compileall, синтаксис launcher, сравнение файлов и git diff --check прошли.

Полный старый набор BB-24 не запущен: в настроенном Python-индексе нет
`pgserver==0.1.4`. Его файлы и зависимости сохранены без изменения.
Современные SQL-регрессии выполнялись на установленной PostgreSQL.
Реальные Telegram WebView, доставка сообщений, облачные RLS и хранение файлов
не проверялись. Для них нужно отдельно разрешённое интеграционное окружение.

Дополнительный прогон собранного frontend выявил старую ошибку тестового стенда:
HTTP-сценарий пропускался внутри тела теста, но fixture уже разрешал внешнюю
попытку API-запроса к Supabase с фиктивной авторизацией. Исправлено отдельным
коммитом: пропуск до открытия браузера и запрет внешнего адреса в HTTP-режиме.
Production SQL не выполнялся, настоящие credentials не использовались.
Состояние облачной базы не проверялось. Проверки не дают оснований утверждать,
что production готов к публикации.

Сканирование файлов на секреты, приватные ключи, DSN, токены и личные данные
не выявило действительных секретов. Совпадения относятся к явно фиктивным
тестовым значениям и контактам авторов лицензированных зависимостей.
В frontend сохранён существующий публичный publishable key и URL проекта;
это клиентская конфигурация из основной main, не серверный секрет.
Его безопасность зависит от серверной авторизации и RLS; облачный аудит не проводился.
Автоматический поиск не является гарантией отсутствия всех возможных секретов.

Push, merge в main, deployment, изменения webhook и облачных настроек не выполнялись.
Telegram Bot API не вызывался. Исходные ветки, worktrees и резервные копии сохранены.
