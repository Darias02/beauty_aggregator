# Beauty Booking локально на Mac

1. Откройте папку `beauty_aggregator` в Finder.
2. Дважды нажмите `Open Beauty Booking.command`.
3. Браузер откроет http://127.0.0.1:8075. Оставьте окно Terminal открытым.

Нужен установленный Python 3.10 или новее. Если его нет, запуск покажет сообщение;
установите Python с python.org. Для preview не нужны pip, Node, Docker, ключи или `.env`.
Если macOS блокирует файл, откройте его через контекстное меню Finder → Открыть.
Альтернатива из Terminal в папке проекта: `python3 tests/bb75/serve_mock.py --open`.
Не открывайте `webapp/index.html` напрямую и не запускайте обычный static server:
эти способы не включают изоляцию mock-окружения.

В профиле можно переключиться между клиентом и мастером. В каталоге есть тестовый
маникюр и свободный слот на 20 декабря 2099 года. Для проверки календаря создайте
свой слот на будущую дату через меню мастера. Затем переключитесь в клиента,
запишитесь на него, вернитесь в мастера и подтвердите или отклоните заявку.
Клиент может отменить запись, мастер может отменить занятый или удалить свободный слот.
Архив клиента показывает отменённые записи. Можно менять имена, адрес мастера и аватар.
Загрузка аватара возвращает тестовую картинку, а не сохраняет выбранный файл.

Чтобы остановить сервер, нажмите Ctrl+C в Terminal. Повторный запуск сбрасывает все
профили, слоты и записи. Вкладки одного запущенного preview используют общие данные.
Если порт 8075 занят, новый запуск завершается с ошибкой; чужой сервер не открывается.

## Что здесь фиктивное

Telegram identity, haptics, popup и ссылки поддержки заменены mock. Popup отображается
как браузерное сообщение `MOCK`. Авторизация и подпись initData не проверяются.
Каталог, профили, слоты, записи и уведомления обрабатываются существующим MockAPI в памяти.
Нет настоящей базы, хранения аватаров, отправки сообщений, RLS или транзакций Supabase.
Шрифты используются системные, внешний SDK не загружается. Дизайн приложения не менялся.

## Изоляция и проверка

Сервер слушает только 127.0.0.1, отдаёт локальный API-конфиг с фиктивным ключом,
не читает `.env` и не содержит внешнего HTTP-клиента. Неподдерживаемые API возвращают
ошибку. Если локальную конфигурацию нельзя подготовить, сервер не стартует;
если она повреждена во время работы, config.js возвращает 503.
CSP запрещает внешние подключения, изображения, скрипты, формы и фреймы.
Дополнительный fetch guard отклоняет внешние URL; ссылки Telegram остаются mock-действиями.
Production Supabase, Telegram Bot API, Vercel и Railway для этого запуска не используются.

Для разработчика остаётся существующий набор `tests/bb75`, зависимости в его
`requirements.txt`, инструкция в `tests/bb75/README.md`. Он проверяет профили,
навигацию, каталог, города, календарь, публикацию и удаление слота, создание,
подтверждение, отклонение и отмену записи, ошибки сети/401/500/JSON, повтор после
ошибки и повторные нажатия. Дополнительный HTTP-сценарий проверяет ручной preview
без подмены ответов API внутри Playwright. PNG, traces и JUnit сохраняются локально
в `tests/bb75/artifacts/` и не коммитятся.

До переноса в основной репозиторий нужно согласовать состав переносимых frontend
изменений и локальных инструментов, отдельно от release/backup истории BB-73–BB-77,
и повторить этот набор проверок после переноса. Реальные Telegram WebView, подписи,
RLS, конкурентные записи и доставка уведомлений потребуют отдельного разрешённого
интеграционного окружения. Этот этап его не подключает и не публикует приложение.
